**IMPLEMENTATION DETAILS:**

1. **The "Sticky" Canvas (HeadphoneScroll.tsx → BrewBeatsScroll.tsx):**
   - Create a component called `BrewBeatsScroll.tsx` in `src/components/`.
   - Container: `h-[400vh]` (4x viewport height for scroll room).
   - Inside: a `<canvas>` element that is `sticky top-0 h-screen w-full`.
   - Canvas is centered and scales correctly on mobile (contain fit).
   - **If using image sequence:** Load frames from `/public/frames/` with naming convention `frame_[i]_delay-0.04s.webp` (120 frames). Place your exported webp frames there.
   - **If no image sequence available (PREFERRED for this project):** Draw a PROCEDURAL animation on canvas:
     - Frame 0-30 (0-25% scroll): A stylized coffee cup with steam rising (vector paths, caramel/cream strokes on espresso background).
     - Frame 30-70 (25-58% scroll): The cup "dissolves" — particles scatter outward, morphing into circular waveform/equalizer bars radiating from center.
     - Frame 70-100 (58-83% scroll): Full waveform visualization — equalizer bars pulsing, musical notes floating, sound waves rippling outward.
     - Frame 100-120 (83-100% scroll): Everything converges into the BrewBeats logo / a "play" button shape.
   - Use `useScroll` from Framer Motion to map scroll progress (0→1) to frame index (0→119).
   - Draw the current frame to canvas on every scroll tick using `useMotionValueEvent` or `useTransform`.

2. **The Scroll Logic:**
   - Use `useScroll({ target: containerRef })` scoped to the scroll container.
   - `useTransform(scrollYProgress, [0, 1], [0, 119])` for frame mapping.
   - On each frame change, redraw the canvas.
   - For procedural: render the appropriate animation state based on progress float (0.0 → 1.0) — no need for discrete frames, draw directly from progress value.
